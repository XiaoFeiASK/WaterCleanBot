## 1. 系统概述

### 1.1 项目背景

水面清洁机器人远程管理系统是为水域清洁作业打造的综合性管理平台，实现对水面清洁机器人、智能船坞、水域环境的远程监控、调度和管理。系统覆盖设备全生命周期管理、任务智能调度、水域环境监测、预警告警等核心业务场景。

### 1.2 系统目标

- **设备远程管控**：实现对清洁机器人及船坞的实时监控、指令下发、状态管理
- **任务智能调度**：基于设备状态、水域范围自动/人工调度清洁任务
- **环境监测分析**：采集水质、水深等环境数据，提供长期趋势分析
- **预警告警体系**：多维度预警规则配置，实时推送预警信息
- **权限精细管控**：基于RBAC模型实现功能权限和数据权限分级管理

## 3. 系统架构设计

### 3.1 五层架构

系统采用分层微服务架构，从下到上分为五层：

#### 第一层：设备与感知层 (IoT Layer)
- **清洁机器人**：搭载电池、垃圾舱、GPS、摄像头、激光雷达等传感器
- **智能船坞**：基站停泊、太阳能供电矩阵、垃圾回收池
- **环境传感器**：水深传感器、水质检测仪（pH/溶解氧/浊度/总磷/总氮）
- **视频设备**：前后置摄像头、船坞对接摄像头
- **激光雷达**：河岸/船坞扫描，生成点云数据

#### 第二层：通信层 (Communication Layer)
- **MQTT**：设备遥测数据上报、指令下发（低延迟、高可靠）
- **WebRTC**：实时视频流传输（P2P，低延迟）
- **WebSocket**：后台实时数据推送（预警、状态变更）
- **HTTP/REST API**：常规CRUD操作、文件上传下载

#### 第三层：数据处理层 (Data Processing Layer)
- **时序数据引擎**：TimescaleDB/InfluxDB，存储遥测数据、环境数据
- **点云处理服务**：激光雷达数据处理，3D建模、轮廓提取
- **视频流处理**：H.265转码、AI异常检测（障碍物识别、水质异常）
- **预警引擎**：规则匹配引擎，支持单值/区间/多指标关联阈值

#### 第四层：应用服务层 (Application Service Layer)
- 设备管理服务、水域管理服务、任务调度服务、预警管理服务
- 设备编队服务、水质报告服务、权限认证服务(RBAC/JWT)
- 消息通知服务、地图服务(GIS)、文件存储服务、日志服务、全局搜索服务

#### 第五层：展示与交互层 (Presentation Layer)
- **总览看板**：统计/轨迹/通知/环境
- **设备控制台**：地图/航线/3D/监控/水质/水深
- **管理后台**：设备/水域/任务/预警/账号/权限
- **系统设置**：个人中心/偏好/搜索

## 5. 功能模块设计

### 5.1 设备管理模块

#### 5.1.1 设备数据采集

**采集数据类型：**

| 数据类别 | 具体指标 | 采集频率 | 存储策略 |
|----------|----------|----------|----------|
| 设备数据 | 电量、垃圾舱容、运行状态、GPS定位、工作里程、速度、船舱进水 | 5秒 | 时序DB，保留1年 |
| 环境数据 | 水深、pH、溶解氧、浊度、总磷、总氮、水温 | 30秒 | 时序DB，保留5年 |
| 船坞数据 | 停泊状态、太阳能电压/电流、垃圾池满载率 | 60秒 | 时序DB，保留1年 |
| 视频流 | 前后置摄像头实时流 | 实时 | 录像保留30天 |
| 点云数据 | 河岸/船坞扫描数据 | 按需 | 原始数据保留90天 |

**数据处理流程：**
1. 设备通过MQTT上报遥测数据
2. telemetry-service接收并验证数据
3. 写入TimescaleDB时序表
4. 预警引擎实时检测阈值
5. WebSocket推送到前端看板

#### 5.1.2 指令下发

**指令类型：**

| 指令 | 说明 | 优先级 | 需确认 |
|------|------|--------|--------|
| START | 启动设备 | 普通 | 是 |
| STOP | 停止设备 | 高 | 是 |
| RETURN | 返航充电 | 高 | 是 |
| CLEAN_BIN | 清理垃圾舱 | 普通 | 是 |
| EMERGENCY_STOP | 紧急停机 | 紧急 | 否 |
| START_COASTAL | 启动沿岸任务 | 普通 | 是 |
| PLAN_ROUTE | 下发航线 | 普通 | 是 |

**指令下发流程：**
1. 后台发送指令 → command-service
2. 通过MQTT下发到设备
3. 设备执行并返回ACK
4. 超时未ACK则重试（最多3次）
5. 记录指令日志

**核心功能：**
- 水域CRUD：创建/查询/修改/删除水域信息
- 地图绘制：在AMap上绘制水域范围多边形

### 5.3 任务管理模块

**任务进度计算逻辑：**

```
任务进度 = (已清洁面积 / 目标清洁面积) × 100%

已清洁面积 = 设备轨迹在目标水域范围内的覆盖面积
目标清洁面积 = 任务关联的水域范围面积
```

**任务状态机：**

```
创建 → 待执行 → 执行中 → 已完成
                ↓        ↓
              已暂停 → 执行中
                       ↓
                     已取消
```

### 5.4 预警管理模块

#### 预警规则类型

**1. 单值阈值**
```
当 指标值 {>, <, =, >=, <=} 临界值 时触发
示例：电量 < 25% → 触发低电量预警
```

**2. 区间阈值**
```
当 指标值 < 下限 或 指标值 > 上限 时触发
示例：pH值 < 6.5 或 pH值 > 8.5 → 触发pH异常预警
```

**3. 多指标关联阈值**
```
当 多个指标条件同时满足时触发
示例：设备离线 AND 电量 < 30% AND 离线时长 > 15分钟 → 触发设备失联预警
```

#### 预警处理流程

```
数据采集 → 预警引擎规则匹配 → 生成预警记录 → 推送看板/站内信/短信
                                    ↓
                              人工处理 → 关闭预警
```

### 5.5 权限管理模块

**RBAC模型：**

```
用户(User) → 角色(Role) → 权限(Permission)
                ↓
           数据权限(Data Scope)
```

**权限类型：**
- **功能权限**：页面访问、按钮操作（查看/新增/编辑/删除）
- **数据权限**：数据范围控制（全部水域/指定水域/仅关联水域）

**权限矩阵示例：**

| 功能模块 | 超级管理员 | 管理员 | 操作员 | 观察员 |
|----------|-----------|--------|--------|--------|
| 设备管理 | 全部 | 全部 | 查看+操作 | 查看 |
| 任务调度 | 全部 | 全部 | 创建+干预 | 查看 |
| 预警规则 | 全部 | 配置 | 查看 | 查看 |
| 账号管理 | 全部 | 查看 | 禁止 | 禁止 |

## 6. 数据库设计

### 6.1 核心表结构

#### devices (设备表)
```sql
CREATE TABLE devices (
    id VARCHAR(20) PRIMARY KEY,           -- AC-001

    last_heartbeat TIMESTAMP,             -- 最后心跳时间
    gps_location GEOGRAPHY(POINT),        -- GPS坐标
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

#### water_areas (水域表)
```sql
CREATE TABLE water_areas (
    id VARCHAR(20) PRIMARY KEY,           -- WA-001
    name VARCHAR(100) NOT NULL,           -- 苏州河-黄浦段
    area_km2 DECIMAL(10,2),               -- 面积
    boundary GEOGRAPHY(POLYGON),          -- 水域范围多边形
    center_lng DECIMAL(10,6),             -- 中心经度
    center_lat DECIMAL(10,6),             -- 中心纬度
    status VARCHAR(20) DEFAULT 'active',  -- active/paused
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### tasks (任务表)
```sql
CREATE TABLE tasks (
    id VARCHAR(30) PRIMARY KEY,           -- TK-20260710-001
    name VARCHAR(100) NOT NULL,
    water_area_id VARCHAR(20) NOT NULL,
    device_id VARCHAR(20) NOT NULL,
    status VARCHAR(20) DEFAULT 'pending', -- pending/running/paused/completed/cancelled
    progress DECIMAL(5,2) DEFAULT 0,      -- 0-100
    scheduled_at TIMESTAMP,               -- 预设安排时间
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    created_by INT,
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### alert_rules (预警规则表)
```sql
CREATE TABLE alert_rules (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    rule_type VARCHAR(20) NOT NULL,       -- single/range/multi
    target_type VARCHAR(20),              -- device/water_area/environment
    target_id VARCHAR(20),
    conditions JSONB NOT NULL,            -- 阈值条件（JSON）
    alert_level VARCHAR(20) DEFAULT 'warning', -- danger/warning/info
    push_channels JSONB,                  -- ["dashboard", "message", "sms"]
    enabled BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT NOW()
);
```

**conditions JSONB示例：**
```json
// 单值阈值
{"metric": "battery", "operator": "<", "value": 25}

// 区间阈值
{"metric": "ph", "min": 6.5, "max": 8.5}

// 多指标关联
{"conditions": [
  {"metric": "status", "operator": "=", "value": "offline"},
  {"metric": "battery", "operator": "<", "value": 30},
  {"metric": "offline_duration", "operator": ">", "value": 15}
], "logic": "AND"}
```

    role_id INT REFERENCES roles(id),

# 平台下发
command/{device_id}/start             # 启动
command/{device_id}/stop              # 停止
command/{device_id}/return            # 返航
command/{device_id}/emergency_stop    # 紧急停机

## 9. 安全设计

### 9.1 认证与授权

- **JWT认证**：登录后签发JWT Token，有效期2小时，支持刷新
- **RBAC权限模型**：基于角色的访问控制，功能权限+数据权限
- **API网关**：统一鉴权入口，Token验证、限流、熔断

### 9.2 数据安全

- **传输加密**：全站HTTPS，MQTT使用TLS加密
- **密码存储**：bcrypt哈希存储，加盐10轮
- **敏感数据**：手机号脱敏显示（138****8888）
- **SQL注入防护**：ORM参数化查询
- **XSS防护**：输入过滤、输出编码

### 9.3 设备安全

- **设备认证**：一机一密，MQTT连接使用设备证书
- **指令签名**：关键指令使用HMAC签名验证
- **防重放攻击**：指令携带时间戳和Nonce
